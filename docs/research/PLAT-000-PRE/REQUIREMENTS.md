# 需求与判断边界

评估日期：2026-10-11，Asia/Shanghai。来源：原样归档的 `EXECUTION_PROMPT.md`。以下 ID 固定，不以宣传功能表替代实现证明。

## 批准基线

单租户、可私有化、各业务系统独立部署与持有数据；元数据驱动统一业务运行时；模块化单体与稳定插件/业务包。Java + Spring Boot + jOOQ + PostgreSQL，React + TypeScript。一业务对象一物理表、字段强类型；JSONB 仅用于定义与受控扩展。身份、权限、约束、审计贯穿 UI/API/MCP/Action/Flow。

语言与具体实现方式可讨论，但本轮不得切换。对象存储、权限模型、动态对象机制的偏差必须显式报告。

## 稳定需求

| ID | 目标要求 | 必须核对的边界 |
|---|---|---|
| R01 | 对象、字段、布局、验证、公式、全局选项值集、选项依赖、权限、Action、应用/导航元数据化 | 个别子能力不能代表整项完整覆盖；共享值集与依赖规则单查 |
| R02 | 运行时新增普通对象/字段，无对象专属代码重建部署 | 区分运行时解释/DDL、构建时代码生成、EAV/JSON 扩展 |
| R03 | 元数据版本、依赖、变更、批量导入导出、环境迁移、失败恢复 | Git/备份不是发布治理；DDL 与数据迁移、回退单查 |
| R04 | 配置自动获得 CRUD、查询、批量、主子复合操作 | 单项 CRUD 不证明主子事务、批量权限与部分失败语义 |
| R05 | 各类 Metadata API；API/Action Schema 自描述、版本、认证、限流 | 不只数据 API；自定义 Action 输入/输出与发布版本 |
| R06 | MCP Server，统一元数据自动形成对象与 Action 工具 | Client/固定工具/OpenAPI 包装不等于动态业务工具 |
| R07 | AI 委托真实用户，禁止客户端自报越权身份，同步/异步身份审计 | token 主体、服务账号、队列用户与撤权一致性 |
| R08 | Profile/Permission Set 等价模型；对象/字段/记录、共享、组织/角色层级 | 角色菜单不够；管理员绕过与字段读写分开 |
| R09 | 查询/聚合/导出/搜索/批量/Flow/Action 统一权限 | 每个执行入口都需后端证据，含可信插件的绕过边界 |
| R10 | Flow、记录/定时/屏幕触发、长任务、重试、事务边界、流程版本 | 同步 hook、状态机、DAG、人工任务不可混为一谈 |
| R11 | 多级审批、会签/或签、分支、任务授权、状态锁定、日志/通知 | 简单审批状态机不能当全功能审批引擎 |
| R12 | 配置入/出站、映射、凭证、幂等、重试、监控 | webhook/HTTP node 不是完整集成治理 |
| R13 | 站内通知、企微，后续 IM/邮件/短信可插拔 | 官方免费/商业/需自写通道分别判断 |
| R14 | 跨对象搜索分组、中文/精确、权限与撤权一致性 | 索引存在不代表权限安全、中文质量或即时撤权 |
| R15 | App/Tab、列表/详情、相关列表、明细行内新增编辑 | 内嵌表格与保存事务、批量编辑不同 |
| R16 | 管理台、动态布局/表单、默认值驱动显隐、依赖选项/必填 | 前端规则须对应 API 校验 |
| R17 | 可复用组件协议、跨对象绑定、键盘/错误/可访问性 | 本轮静态代码不能证明实际无障碍体验 |
| R18 | 多语言字段/选项/UI，机器值与标签分离，翻译导入导出 | UI 翻译不代表业务标签全链路 |
| R19 | 强类型表、关系/金额精度、事务/并发/幂等/审计/事件一致性 | decimal、引用、DDL、outbox 与失败行为分别核查 |
| R20 | 独立私有化，核心运行不依赖厂商云控制面 | 商业激活/续订与平台启动、离线运行分开 |
| R21 | 插件/业务包、升级、数据/配置退出 | backup 不等于可迁出；附件关系/流程历史也需导出 |
| R22 | 真实构建/测试/安全修复与合理运维 | 找到测试不等于执行；活动不等于安全或发布质量 |

## 候选分类与矩阵协议

- A：接近 Java/PostgreSQL 主线，可直接讨论适配；不因此自动优先。
- B：产品能力接近但需后端/前端/存储变化，仅提出待批准 ADR。
- C：只具备组件/设计价值，不能称为整个平台。

能力维度：`COMMUNITY_NATIVE`、`OFFICIAL_COMMERCIAL`、`CUSTOM_EXTENSION`、`CORE_REWRITE`、`UNSUPPORTED`、`UNKNOWN`。证据维度：`DOC_ONLY`、`SOURCE_TRACED`、`EXISTING_TEST_FOUND`、`RUNTIME_VERIFIED`、`BLOCKED`。同一需求含多个子项时保留条件与缺口，不强行给整体 PASS。

事实分类：`VERIFIED_FACT` 为可定位材料事实；`DESIGN_DECISION` 是未批准建议；`ASSUMPTION` 标明验证办法；`UNVERIFIED` 不作为通过依据。本轮不设置总分，不让易用性抵消许可证、权限与存储阻断项。

## 待讨论变量

尚未决定：未来是否向客户/集团不同法人交付、是否接受收费模块、是否接受服务端换栈、是否要求所有流程自动以用户身份运行、元数据发布是否必须在线零停机。缺失答案不会自动成为排除候选的理由；按不同场景报告影响。

路线建议须比较直接采用、官方配置、独立插件、有限补丁、核心改写。无论建议为何，先报告后审查，不恢复骨架。
